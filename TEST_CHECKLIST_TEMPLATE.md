# MessageServiceGo Test Checklist Template

Шаблон для ручного тестирования `MessageServiceGo`.

```text
Дата:
Тестировщик:
```

## 2. Docker и контейнеры

- [ ] `docker compose up --build -d` выполняется без ошибок.
- [ ] `docker compose ps` показывает запущенные контейнеры:
  - [ ] `message-service`
  - [ ] `messaging_postgres`
  - [ ] `msngr_nats`
- [ ] `message-service` не перезапускается циклически.
- [ ] В логах `message-service` есть сообщение `server listening on :8080`.

Команда для логов:

```powershell
docker logs message-service
```

## 3. База данных

- [ ] В PostgreSQL созданы таблицы:
  - [ ] `chats`
  - [ ] `chat_members`
  - [ ] `messages`
- [ ] Таблица `chat_members` содержит уникальность по паре `chat_id, user_id`.
- [ ] Таблицы `chat_members` и `messages` связаны с `chats` через `ON DELETE CASCADE`.

Проверка:

```powershell
docker exec -it messaging_postgres psql -U postgres -d messaging_db
```

```sql
\dt
\d chats
\d chat_members
\d messages
```

## 4. Базовая доступность API

- [ ] Запрос без `X-User-Id` возвращает `401`, если endpoint требует пользователя.
- [ ] Запрос с `X-User-Id` возвращает ожидаемый результат.

Пример:

```powershell
Invoke-RestMethod -Uri "http://localhost:8080/chats/" -Method Get -Headers @{ "X-User-Id" = "user1" }
```

## 5. Чаты

- [ ] Создание чата работает.
- [ ] В ответе есть `id` и `name`.
- [ ] Создатель автоматически добавляется в участники чата.
- [ ] Список чатов пользователя содержит созданный чат.
- [ ] Получение чата по `id` работает для участника.
- [ ] Получение несуществующего чата возвращает корректную ошибку.
- [ ] Получение чата пользователем, который не является участником, возвращает корректную ошибку.
- [ ] Удаление чата участником работает.
- [ ] После удаления чат больше не возвращается.

## 6. Участники чата

- [ ] Получение списка участников работает.
- [ ] Добавление участника работает.
- [ ] Повторное добавление того же участника возвращает корректную ошибку.
- [ ] Добавление участника пользователем без прав возвращает корректную ошибку.
- [ ] Удаление участника работает, если запрашивающий пользователь имеет права.
- [ ] Удаление несуществующего участника возвращает корректную ошибку.
- [ ] Удаление участника пользователем без прав возвращает корректную ошибку.
- [ ] Поведение при удалении последнего участника проверено.

## 7. Сообщения

- [ ] Создание сообщения работает для существующего `chat_id`.
- [ ] В ответе есть:
  - [ ] `id`
  - [ ] `chat_id`
  - [ ] `content`
  - [ ] `sender_id`
  - [ ] `created_at`
- [ ] Создание сообщения в несуществующий `chat_id` возвращает корректную ошибку.
- [ ] Создание сообщения пользователем без прав возвращает корректную ошибку.
- [ ] Получение истории сообщений работает для участника чата.
- [ ] Получение истории сообщений без пользователя возвращает корректную ошибку.
- [ ] Получение истории сообщений пользователем не из чата возвращает корректную ошибку.
- [ ] Сообщения возвращаются в ожидаемом порядке.
- [ ] `limit` ограничивает количество сообщений.
- [ ] `offset` сдвигает выборку.
- [ ] Обновление сообщения автором работает.
- [ ] Обновление сообщения не автором возвращает корректную ошибку.
- [ ] Обновление несуществующего сообщения возвращает корректную ошибку.
- [ ] После обновления есть ожидаемый признак редактирования, если он предусмотрен требованиями.
- [ ] Удаление сообщения автором работает.
- [ ] Удаление сообщения не автором возвращает корректную ошибку.
- [ ] Удаление несуществующего сообщения возвращает корректную ошибку.

## 8. Негативные REST-кейсы

- [ ] Создание чата без `name` возвращает `400`.
- [ ] Создание чата с пустым `name` возвращает `400`.
- [ ] Создание чата с названием из пробелов обработано корректно.
- [ ] Создание сообщения без `chat_id` возвращает `400`.
- [ ] Создание сообщения без `content` возвращает `400`.
- [ ] Создание сообщения с пустым `content` возвращает `400`.
- [ ] Создание сообщения с `content` из пробелов обработано корректно.
- [ ] Создание сообщения без `sender_id` возвращает `400`.
- [ ] Запрос с нечисловым `chat_id` возвращает `400`.
- [ ] Запрос с нечисловым `message_id` возвращает `400`.

## 9. Кодировка

- [ ] Сообщение на латинице сохраняется и читается корректно.
- [ ] Сообщение на кириллице сохраняется и читается корректно.
- [ ] Проверено отображение кириллицы:
  - [ ] в API-ответе
  - [ ] в JSON-файле
  - [ ] в PostgreSQL
  - [ ] в консоли

## 10. WebSocket

Подключение:

```text
ws://localhost:8080/ws/chat?chat_id=1&user_id=user1
```

Для Postman:

```text
Origin: http://localhost:8080
```

- [ ] WebSocket-подключение открывается с валидными `chat_id` и `user_id`.
- [ ] WebSocket-подключение работает при корректном `Origin`.
- [ ] Без корректного `Origin` поведение проверено.
- [ ] Подключение без `chat_id` или `user_id` обработано корректно.
- [ ] Подключение пользователем не из чата возвращает корректную ошибку.
- [ ] Второй пользователь может подключиться к тому же чату.
- [ ] Сообщение типа `message` рассылается подключенным пользователям.
- [ ] Событие `typing` рассылается подключенным пользователям.
- [ ] После отключения пользователя сервис не падает.

Пример сообщения:

```json
{"type":"message","message":"hello from ws"}
```

Пример typing:

```json
{"type":"typing"}
```

## 11. REST и WebSocket

- [ ] Сообщение, созданное через REST API, доставляется активным WebSocket-клиентам, если это предусмотрено требованиями.
- [ ] Сообщение, отправленное через WebSocket, сохраняется в БД, если это предусмотрено требованиями.
- [ ] Сообщение, отправленное через WebSocket, отображается в истории, если это предусмотрено требованиями.
